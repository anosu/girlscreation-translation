# 当前工作流架构

本文描述当前实现。接入只需理解[资源契约](adapters.md)和 collect 接口；内部计划不属于适配器 API。Agent 按需阅读原始材料和紧凑待办，交付文件保存原文到译文。

## 数据流

```text
适配器 collect → sync 保存不可变资源 → plan 离线生成字典待办
    → Agent 分工作包阅读、提交、修订 → 独立校验 → publish 原文到译文字典
```

获取范围由游戏适配器决定。同步失败只留下未引用对象，不替换上次有效快照；成功后生成新的快照指针。运行中的计划绑定不可变文件，新的同步不会自动改变其依据。文件内容被修改则阻止继续校验和完成。

## 模块

| 模块 | 职责 |
| --- | --- |
| resources.py | 公共 dialogue/text 资源格式 |
| dictionaries.py | 文件路径、JSON 字典定位、结构与路径重叠校验 |
| adapters.py、adapters/ | collect 接口、适配器加载、游戏获取与提取 |
| snapshot.py | 本地不可变对象、快照指针和 CI 原文包 |
| prepare.py | 按输出字典选择资源、合并同文待办、记录旧译文 |
| models.py | 内部计划、答案和发布记录；不作为接入格式 |
| session.py、agent.py | 紧凑视图、分页检索、工作包编号、答案保存和校验 |
| translate.py、codex.py | 每个工作包启动独立 Agent，绑定模型设置并保护输入 |
| glossary.py、validate.py | 术语、格式与提案校验 |
| merge.py、build.py | 多语言预检、指定字典位置写入和 manifest |
| cli.py、ci.py、scaffold.py | 用户命令、CI 和新项目生成 |

## 关键约定

- 阅读材料保留全部原始顺序和重复位置。待办按语言、输出文件、字典路径、精确原文合并；不标准化空格或标签。
- 同一字典的同文只能交付一个译法，跨资源保留上下文引用，冲突不采用最后写入覆盖。
- 资源级上下文和规则只声明一次；模型只读取当前包及按需检索的资料，不读完整 Plan。
- 模型提交短编号，但命令必须带绑定计划的 packet。旧编号不能用于新计划；已接受值要修改时通过带 before 的 revise 显式操作。
- Agent 先处理明确的术语资源和配置的标准名称来源，没有术语资源也能工作。名称译法从输出字典读取，不复制到术语表；补充术语提案需有真实原文证据。
- --limit 限制有待办的资源数，先比较已有译文再分配额度；已完成资源保留为免费上下文。共享输出文件的资源不能拆开，没有可容纳的待翻译组时报错，暂缓待办单独计数。整个计划完成并通过独立校验后才发布。
- 每个内部 Task 直接记录 output、path、source、before；不再包一层单元素 targets 或重复保存空上下文。名称来源按字典登记一次，统一读取为标准译名映射，不逐个名称建立引用记录。
- 计划格式由框架内部版本控制，与缓存目录名分离。旧计划在原目录重新生成，仍适用的答案经校验后复用。标准名称来源配置参与计划身份和发布预检，当前译法参与答案政策指纹。
- 发布保留人工修改冲突检查、多目标预检、原子文件替换和 manifest 最后写入；不承诺并发写同一目标或多文件事务。

## 边界与限制

框架不承诺本次快照覆盖全游戏，也不检查远端最新版本。check 只校验现有本地交付，不需要适配器或下载缓存。

分页上限按字符实现，用于控制单次工具输出大小，不等于精确 token 预算；模型会话开销仍需实测。同一包非常长时可以分页、保存答案并在失败后恢复，不保证不会触发模型自身上下文压缩。

没有常驻服务、数据库、任务租约、模型路由或细粒度依赖图。同一目标串行写入。未引用的快照对象暂不自动回收，避免删除旧计划所需资料；需要时可整体归档不再使用的工作目录。
