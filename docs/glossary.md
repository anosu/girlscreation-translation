# 项目术语表

每种语言独立维护补充术语，初始可为 {}。没有其他标准来源的术语填写 translation：

```json
{
  "アリス": {"translation": "爱丽丝"},
  "Save": {"translation": "保存", "categories": ["text"], "note": "界面操作"}
}
```

categories 可省略，表示全局。当前任务分类为 dialogue、text 或 terms；显式范围优先于全局。同一原文可使用记录数组，但范围不能重叠。

名称等已有交付字典可以直接作为标准来源，在目标配置中设置：

```toml
term_sources = [{ file = "names.json" }]
```

路径相对该目标的 translations 目录；可增加 path 指向文件内的字典。框架直接读取已有译法，不将 term=true 资源的译文复制到 glossary。本轮已接受的新译名保存在工作目录，Agent 翻译后续剧情时应一并参考；发布后才写入标准字典。

标准来源里的名称需要说明时，可以只写 note，不重复 translation：

```json
{
  "村人": {"note": "普通角色称呼"}
}
```

只有能从配置的标准来源解析到译法时，省略 translation 才有效。多个标准来源对同一名称给出不同全局译法，或者 glossary 中重复的全局译法与标准来源冲突，都会明确报错。分类限定的补充术语仍按原有范围规则选择。

term=true 用于本轮明确的术语资源；term_sources 用于跨次运行读取已有标准字典，两者可以一起使用。说话人字段本身不自动生成名称翻译任务；适配器应把本次剧情出现的非空名称汇总为名称资源。没有名称资源也可以直接翻译剧情。

术语类待译项若已有确定译法，框架会尝试复用；提交时也会检查是否与已确定译法一致。普通台词、标题及其他文本可由 Agent 按需查阅相关术语，并按语境区分同文异义；框架不会将角色名直接当作标题答案。明确的逐条硬约束可放入 rules.required_terms。

从旧版本迁移时，先配置标准来源。旧版自动复制到 glossary 的同名 translation 可移除，保留需要的 note；不要为了同步 names 而长期维护两个译法副本。运行中的名称来源若被修改，当前会话或发布会报告冲突；重新规划并执行 translate 后使用新的标准译法。

新增或修改术语由维护者更新 glossary 或标准字典，框架不会自动改写术语表。句内术语不是机械子串替换，语义一致性仍需审阅。
